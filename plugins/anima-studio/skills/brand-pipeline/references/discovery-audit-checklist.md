# Phase 1 — Discovery & Audit checklist

Run this before producing anything. The goal is an honest current-state read, not a pitch.

## 1. Inventory existing assets first
- [ ] Search the target project for existing brand/design-system docs (`brand.md`, `tokens.md`, design
      ADRs, style guides, a screen inventory, a component library, a prompt library used for prior design
      generation)
- [ ] Note each decided element found and its status (draft vs. stable/locked) — do not treat locked
      decisions as open
- [ ] Note each explicitly open question already tracked (e.g. an "Open" table in an existing brand doc)
- [ ] Collect any moodboard or reference imagery already gathered, and any newly supplied by the user

## 2. What works / what doesn't
- [ ] List specific things in the current product/brand that are working and should survive the pipeline
- [ ] List specific pain points — be concrete (a screen, a flow, a stated user complaint), not generic
      ("branding feels inconsistent" is not actionable; "the app icon reads as an eye, not an orbit, below
      24px" is)

## 3. Audience & positioning
- [ ] Who is this for, specifically — not a generic persona, the actual target user
- [ ] Who are the real competitors/reference points, and how should this brand differ from them
- [ ] What is the core business objective this identity pass needs to serve (e.g. conversion, trust,
      premium positioning, retention)

## 4. Output
A short audit document: current-state summary, works/doesn't-work list, audience, positioning, objectives,
and an explicit list of what Phase 1 found already-decided vs. still-open. Get user approval on this before
Phase 2.
